# Go（围棋）子项目设计文档

> 目标：按"自我对弈强化学习"路线训练一个围棋 AI，从 9 路小棋盘开始，
> 逐步升级到 19 路大棋盘 + 大模型，多晚续训累积，最终对弈 KataGo 等现有引擎。

## 1. 总体分期（按晚滚动）

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| P0 ✅ | 规则引擎（本目录 `go/board.py`）：提子/劫争/禁自杀/数子终局，5 项测试 | 全部通过 |
| P1 | 9 路自弈：小型 ResNet（4 块×64，~60 万参数）+ MCTS(128)，纯 RL 自我对弈 | 自弈对局局面合理、无自杀/劫违例，可完整终局数子 |
| P2 | 9 路强度爬坡：续训 + 模型倍增（6×96），接入简单政策先验 | 与 P1 网络对抗胜率 ≥60% |
| P3 | 13 路 → 19 路：编码不变，网络加深（10 块×128 → 20 块×256） | 19 路能完整对局 |
| P4 | 对抗现有引擎：安装 KataGo（弱配置/限制搜索），对打计 Elo | 持续升级训练量与模型规模 |

## 2. 状态编码（输入平面，借鉴 AlphaZero）

1. 己方棋子（1 平面）
2. 对方棋子（1 平面）
3. 己方上一手（1 平面）
4. 简单劫点标记（1 平面）
5. 全 1 的颜色平面（1 平面）
6. （可扩展）N-3..N-1 历史局面，各 2 平面

## 3. 动作空间

n×n 棋盘 n² 个点 + pass，即 19 路 362 维。策略头输出 n²+1 logits。

## 4. 网络配置

| 阶段 | 残差块 | 通道 | 参数量（约） |
|---|---|---|---|
| P1 (9路) | 4×64 | 64 | 60 万 |
| P2 (9路) | 6×96 | 96 | 190 万 |
| P3 (13路) | 10×128 | 128 | 600 万 |
| P4 (19路) | 20×256 | 256 | 2500 万 |

价值头：conv1x1 → FC(256) → tanh。策略头：conv1x1 → flatten + pass 偏置。

## 5. 自我对弈参数（首版）

- MCTS：PUCT c=1.6，模拟数 128（9 路）→ 256（13 路）→ 400（19 路）
- 根 Dirichlet 噪声 α=0.03（围棋分支因子大，噪声要尖）
- 温度：前 20 手 T=1，之后 T→0
- 终局：双方连续 pass；数子用中国规则（区域法），贴目 7.5
- 训练：策略 CE（访问分布）+ 价值 MSE（终局胜负），对称增强 8 倍
- 经验池 100 万局面，批 512，lr 2e-3 → 2e-4 余弦

## 6. 与 KataGo 对抗

- 安装：`pip` 无官方包，需下载二进制 + 网络（g170 系列权重太大，用其开源的小网络或
  限制 KataGo 的 maxVisits 到与我们的 MCTS 同等量级，比"纯棋力"更比"搜索效率"）
- 协议：GTP 文本协议封装一个对局驱动器，双方各给相同思考时间
- 记录每局结果 → arena 报告，逐晚追踪

## 7. 风险与对策

- **自弈reward hacking（乱提死子）**：数子前不做死活判定会导致网络学会"送死子"。
  P1 阶段先用"双方 pass 后全子存活"的简化数子观察是否出现该行为；若出现，引入
  简单 B Benson 算法判活或用 policy-guided 小型 play-out 清理死子后再数。
- **算力**：19 路大模型一晚只能跑有限迭代 → 严格断点续训（--resume），多晚累积。
- **劫争多样性**：superko 规则暂用 simple ko，若自弈出现循环局面再加 positional superko。
