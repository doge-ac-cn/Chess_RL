# 从零训练一个五子棋 AI：棋类深度强化学习实战教程

> 本文记录了一个完整可复现的实验：**用行为克隆热启动 + AlphaZero 式自我对弈强化学习，
> 训练一个 28 万参数的小模型，在 15×15 五子棋上执黑对全部内置对手保持不败**，
> 并把模型量化到 302KB 部署到手机。
>
> 教程面向"懂神经网络、但没做过棋类 AI / 强化学习"的读者。所有代码都在本目录下，
> 每一节对应真实的源文件，包括我们踩过的三个坑和修复过程。
> 读完你可以把同一套流程平移到象棋、围棋等其他棋类。

---

## 0. 十秒钟看懂全局

棋类 AI 训练就是一个不断重复的循环：

```
        ┌─────────────── 当前网络 ───────────────┐
        │                                        │
        ▼                                        │
  [自我对弈]  ──产出──▶ [经验数据] ──训练──▶ [新网络] ──考核──▶ 比旧的强？留用 : 丢弃
  (网络左右互搏)         (棋盘+搜索结果)                              │
                                                                    │
                                                    更新"当前网络" ◀─┘
```

- **网络**负责"直觉"：看一眼棋盘，说出每个点的好坏（策略）和谁占优（价值）；
- **搜索（MCTS）**负责"计算"：用直觉引导的树搜索把直觉变成深思熟虑的着法；
- **强化学习**负责"进步"：网络和更强的搜索联手下棋，再把下棋的思考过程喂回给网络。

AlphaGo Zero / AlphaZero 就是这个循环的集大成者。我们的目标是用最小的代码量和
最小的模型把它跑通、跑赢，并且能塞进手机。

## 1. 预备概念（建议 10 分钟读完）

### 1.1 棋类游戏是一个"马尔可夫决策过程"

只要三个东西：

| 概念 | 五子棋里对应 | 代码位置 |
|---|---|---|
| 状态 S | 棋盘上所有棋子 + 该谁走 | `board.py` 的 `Board` |
| 动作 A | 225 个交叉点（15×15）里还没落子的那些 | `Board.candidates()` |
| 奖励 R | 终局才给：赢 +1、输 -1、和 0 | 训练时的 `z` 标签 |

和 Atari 游戏不同，棋类的奖励**只在终局出现**，中间几百步都没有反馈——这决定了
我们不能直接用"奖励回传"的朴素强化学习，而要用"终局结果 + 搜索"来教学。

### 1.2 策略（policy）和价值（value）

网络对棋盘输出两个头：

- **策略头**：225 个点各一个概率，"我下一步想走哪"。类似语言模型 logits→softmax。
- **价值头**：一个 -1~1 的标量，"当前局面我认为自己胜算多大"。

一个网络、两个头、一次前向，这是所有棋类 AI 的标准配置。

### 1.3 为什么是"自我对弈"？

训练一个下棋网络需要标注数据（什么局面该走哪），但没人能穷举 15×15 五子棋的
10^70 量级局面。自我对弈的思路是：**让当前网络自己跟自己下，下完用胜负结果给每个
局面打标签**。对手是自己，意味着数据无限生成、难度自动匹配、且永远不会停止进步。

### 1.4 MCTS：把网络直觉变成深思熟虑

蒙特卡洛树搜索每"想一步棋"会做 N 次模拟（本项目 N=64~256），每次模拟分四步：

1. **选择**：从根节点往下走，每层挑 `Q + c_puct·P·√N/(1+n)` 最大的分支。
   其中 Q 是这条分支的平均价值（网络估的），P 是策略概率（网络估的），
   后半项是"没试过的分支加分项"。这就是 **PUCT 公式**——探索与利用的平衡。
2. **扩展**：走到叶子，调用一次网络，得到叶子的策略 P 和价值 v。
3. **评估**：这个 v 就是叶子的"胜负预测"。
4. **回传**：把 v 沿路径逐层**翻转符号**（我的好消息是对手的坏消息）累加回去。

N 次模拟后，**根节点每个分支被访问的次数比例**就成了一组更高质量的策略——它比
网络裸输出强得多。自我对弈时我们把这个访问分布当作策略的训练目标，相当于让网络
"模仿自己深思熟虑后的决定"，这就是 AlphaZero 学习的核心机制。

## 2. 第一步：把棋盘写出来（`gomoku/board.py`）

没有棋库依赖，100 行以内实现规则引擎，核心是几个后面会反复用到的查询函数：

```python
class Board:
    cells          # (15,15) int8: 0空 1黑 2白
    to_move        # 轮到谁
    def play(r,c) / undo()          # 走子/悔棋（搜索时大量使用，必须 O(1)）
    def winner_after(r,c)           # 刚下的这手有没有形成 ≥5 连
    def candidates(radius=2)        # 有棋子附近的空点（剪枝：不搜全盘 225 点）
    def five_points(p)              # p 方"下一手就赢"的点
    def four_completions(r,c,p)     # p 若走 (r,c)，形成的"四"有哪些成五点
```

三个工程要点：

1. **胜负判定只看最后一手**：连五一定包含刚落的子，沿 4 个方向数连子即可，
   O(8)，不需要全盘扫描。
2. **候选点剪枝**：永远只在"已有棋子的切比雪夫距离 2 内"的空点里找着法。
   搜索空间从 225 降到 ~40，这对后面的 MCTS 速度至关重要。
3. **威胁点查询**：`five_points`（即刻成五点）和 `four_completions`（若走这里
   会形成什么"四"）是后面强制着法、防叉守卫、VCF 证明器共用的地基。
   这类"棋类常识函数"写一次，整条流水线受益。

> **平移到其他棋类**：中国象棋改状态表示（棋子种类）+ 将帅照面/蹩马腿等规则；
> 围棋要加"提子/劫争/禁自杀"。接口保持 `play/undo/status/candidates` 四件套不变。

## 3. 第二步：规则型老师 AI（`gomoku/heuristic.py`）

强化学习冷启动很难，所以先造一个"会下棋的老师"用于热启动（第 5 节）和作为
评估基线。实现是经典的**棋型打分**：

对每个候选空点，沿 4 个方向各取以它为中心的 9 格窗口，把窗口转成字符串
（'1'=己方 '0'=空 '2'=对方/墙），在模式表里查最高分值：

```python
PATTERNS = [
    ("11111", 10_000_000),   # 连五
    ("011110", 300_000),     # 活四（两头都空的四）
    ("211110", 25_000), ...  # 冲四、活三、眠三、活二……
]
总评分 = 我在此落子的进攻分 + 0.8 × 对方在此落子的防守分
```

一层的攻防打分能到业余中等水平，**但没有前瞻**——这恰好是后面检验 RL 成果的
绝佳标尺。这个老师 AI 在本项目里身兼两职：BC 阶段的老师、评估时的对手。

## 4. 第三步：策略价值网络（`gomoku/model.py`）

```python
输入 (B, 4, 15, 15)   # 4 个平面：己方子 / 对方子 / 最后一手 / 执黑标记
  → Conv3x3(48) + BN + ReLU
  → 4 × 残差块 (Conv-BN-ReLU-Conv-BN + skip)   # AlphaGo 的经典主干
  → 策略头: Conv1x1(2) → Conv1x1(1) → flatten → 225 logits
  → 价值头: Conv1x1(8) → flatten → FC(64) → tanh 标量
```

设计取舍：

- **为什么这么小**（284k 参数，AlphaGo Zero 是百万级）：手机部署 + 实验迭代速度。
  搜索会补足网络的深度不足——网络越弱越依赖搜索，但只要"直觉"方向对，
  64 次模拟的 MCTS 就能下出超过网络本身水平的棋。
- **输入编码只要 4 个平面**：己方/对方子、最后一手位置（时序信息的最廉价替代）、
  执黑标记（先手优势不对称）。想加时序可以堆历史平面，实验发现对本项目收益不大。
- **数据用 int8 存**（每局面 900 字节）：6 万条经验约 54MB 内存，float32 会翻 4 倍。

## 5. 第四步：行为克隆热启动（`gomoku/train.py` 的 `bc_dataset`）

### 5.1 做法

直接让 RL 从零自我对弈，前期会浪费大量算力在"乱下"上。先用监督学习给网络一个
像样的起点：

1. 老师 AI 执棋与**随机对手**对弈若干局；
2. **每个局面都用确定性老师的选点重新打标签**（"重标注"技巧，见 5.2）；
3. 策略头交叉熵 + 价值头胜负 MSE，训练若干 epoch。

### 5.2 坑 1：老师互弈 100% 和棋，价值标签全是 0

最初版本让老师 AI 自己跟自己下棋生成数据，结果 **80 局全部下满棋盘成和棋**：

```
positions: 4500, outcome mean/std: 0.0 0.0    ← 价值标签全是 0，价值头学不到任何东西
```

原因：一层攻防打分的棋手互相之间谁也攻不破谁，双方都防守到位直到棋盘下满。
修复：改成"老师 vs 随机对手"——必分胜负、对局快速结束、且随机方位置的标签
天然是 -1，价值标签自动平衡（实测 1274 胜 / 1199 负）。

另一个坑藏在评测里：训练数据是带温度的老师（软策略），而评测用确定性老师，
两者分布不一致导致指标虚低。**重标注**（所有局面统一用确定性老师打标签）同时
解决了标签一致性和对局多样性两个问题。

> **经验**：监督热启动阶段，先花十分钟检查**标签的分布**（价值标签均值方差、
> 策略标签是否可学），比直接开训省几个小时。

## 6. 第五步：自我对弈强化学习（`gomoku/selfplay.py` + 训练主循环）

### 6.1 每一轮迭代做什么

```
for 每轮迭代:
    1. 自我对弈:  24~32 局，当前网络 + MCTS(64 sims) + 根节点 Dirichlet 噪声
                  每手记录 (棋盘编码, MCTS访问分布π, 终局胜负 z)
    2. 训练:      从经验池采样，损失 = 策略CE(π) + 价值MSE(z)，8 对称增强
    3. 晋级赛:    新网络 vs 卫冕网络，双执黑白各半，≥55% 才允许替换 best
    4. 考核:      新网络执黑 vs 老师 AI 胜率（外部度量，防"自我对弈自嗨"）
```

关键细节：

- **Dirichlet 噪声**：根节点先验混入噪声 `P' = 0.25·η + 0.75·P`，强迫搜索探索
  不同开局，否则自我对弈永远重复同一条开局线。
- **访问分布作策略目标**：训练目标不是"赢了这盘"（那是价值头的事），而是
  "搜出每个点的访问次数分布"。这就是网络在模仿搜索。
- **8 对称增强**：棋盘旋转/翻转 8 种等价变换，一份经验顶 8 份，棋类免费午餐。
- **强制着法短路**：自我对弈时"即刻成五"和"必须堵五"两种着法直接落子、跳过
  MCTS（逻辑上必然如此走），省一半时间，策略标签记 one-hot。

### 6.2 坑 2：学习率过高，候选网络"漂移"

第一版 RL 用 lr=1e-3，第 3-4 轮出现明显异常：

```
iter 3: gate=0.5  vs_teacher_black=0.2   ← 候选网络突然被老师打爆
iter 4: gate=0.0  vs_teacher_black=0.8   ← 晋级赛 12 局全败
policy loss: 2.8 → 3.7（持续上升）        ← 越训越偏
```

诊断：自我对弈数据来自弱网络，分布窄且噪声大；高学习率把 BC 学到的先验
迅速冲掉，网络滑进"只会下自我对弈怪棋"的局部。修复三件套：

1. RL 阶段学习率降到 **3e-4**（BC 阶段仍用 2e-3）；
2. 每轮对局 24→32 局，让目标分布更稳；
3. **经验池保留一部分老师数据做锚**（类似 distillation 的防遗忘）。

修复后第 5 轮门控 0.917 一次晋级，之后每个新 best 都不再输给老师。
**晋级门控的价值正在于此**：候选再怎么折腾，best 只会被"证明更强"的网络替换。

## 7. 第六步：给引擎加上"逻辑保底层"（`gomoku/players.py` + `vcf.py`）

纯网络+搜索的引擎有个讨厌的问题：99 手下得很强，偶尔犯一个"看不到对手 3 手后
的必胜叉"的错，一整盘就没了。我们在评估时真实抓到过一局（第 10 节），于是给
最终引擎加了四层**逻辑保证**，从强到弱：

1. **win-now**：我能连五 → 直接下（必然）；
2. **block-five**：对手下一手能连五 → 必须堵（唯一的非输着法）；
3. **防叉守卫（fork guard）**：选完着法后检查——这手棋是否允许对手下一步形成
   "活四/双四"（`four_completions ≥ 2`，即一次制造两个成五点）？若允许，就从
   MCTS 访问数前 6 的候选里换一个不放叉的；如果前 6 个全都放叉，就把对方的
   叉点和成四点本身纳入防御候选、按 MCTS 先验挑一个。
4. **VCF 证明器**（`vcf.py`）：只搜"连续冲四"的强制路线。黑棋每手都制造"四"，
   对手的应手被完全强制，搜到头就是**数学证明级的必胜**——一旦返回路线，
   无论对手怎么应对都输。可靠性设计：对手若存在任何成五点则证明失败（保守但
   保证不误报）、单完成点的四对手被强制、双完成点的四直接判胜。

> 坑 3 的教训值得展开：评估时抓到一局黑棋速败，复盘发现白棋一手棋同时形成
> 两个成五点（先手方活四叉），黑棋必败。这**不是 bug**——堵五短路每一手都
> 正确执行了——而是 MCTS(128) 没提前 3 手拆解对手的三连。加入防叉守卫后，
> 同一评测协议黑棋胜率从 65% 直接拉到 100%，守卫平均每局出手 1.5 次。
>
> **经验**：棋类引擎 = 网络直觉 + 树搜索 + 规则逻辑，三者不是竞争关系。
> 逻辑层负责"绝对不能犯的错"，搜索负责"权衡"，网络负责"方向感"。

## 8. 第七步：评估方法论（`gomoku/eval.py` + `gomoku/arena.py`）

训出来的模型强不强，只有打了才知道。我们的评估原则：

- **多对手梯度**：随机 AI（检验执行力）→ 规则老师（检验棋力）→ 初版 checkpoint
  （检验 RL 进步幅度）；
- **双执黑白**：五子棋先手优势极大，只报"总胜率"会误导，必须分开报黑/白；
- **开局多样化**：前 2 手按访问分布带温度采样，避免 100 局都是同一条开局线；
- **双协议复核**：并行快评（多进程池，100 局）+ 顺序确定性复核（20 局），
  防止某一协议的偶然性；
- **记录胜局类型**：每局最后一手是"直接连五 / 堵五 / VCF 证明 / MCTS 选点"，
  以及守卫出手次数——这些数据直接指导下一步改进（防叉守卫就是这么发现的）。

## 9. 实验记录（真实数据）

### 9.1 训练配置

| 项 | 值 |
|---|---|
| 棋盘 / 规则 | 15×15 自由规则（无禁手，≥5 连胜） |
| 网络 | 4 残差块 × 48 通道，284,322 参数 |
| BC 阶段 | 150 局老师对局 ≈ 2500 局面，lr 2e-3，8 epoch |
| RL 阶段 | 62 轮 × (32 局自我对弈 × MCTS 64 sims)，lr 3e-4，经验池 6 万 |
| 硬件 | RTX 3090（训练）+ 24 进程 CPU（自我对弈），全程 121 分钟 |

### 9.2 训练进展

- 晋级发生在第 1/5/12/13/14/22/32/34/38/39/46 轮——早期密集（能力快速提升），
  后期稀疏（强强对话进步变慢），符合 AlphaZero 类训练的典型曲线。
- 每轮"执黑 vs 老师"考核：前 10 轮波动（最低 0.2，即坑 2 期间），第 22 轮起
  稳定 1.0。
- 价值头损失 0.69 → 0.35（预测胜负越来越准）。

### 9.3 最终战绩（MCTS 128 sims，100 局/对手）

| 对手 | 总战绩 | **执黑** | 执白 |
|---|---|---|---|
| 随机 AI | 100/100 | 50/50 | 50/50 |
| 规则老师 AI | 100/100 | 50/50 | 50/50 |
| 初版 checkpoint | 63/100 | **50/50** | 13/50 |

确定性协议复核：执黑 19/20。合计执黑对老师 **69/70 ≈ 98.6%**，执黑对旧版自己
100%。把搜索加深到 256 sims（手机端可承受的配置）后复测 100 局：**总战绩 100/100，
执黑 50/50、执白 50/50**——搜索强度是免费的棋力来源。五子棋先手优势极大，"执白"
对上任何较强对手都难打，这不影响本项目"**黑棋必胜**"的目标定义——我们要证明的
正是执黑的统治力。

### 9.4 关于"必胜"的诚实讨论

自由规则五子棋在数学上已被证明先手必胜（Allis 1994），但那是全局搜索的结果。
RL 引擎给出的是**工程级保证**：

- win-now / block-five / 防叉守卫是**逻辑必然**的着法层；
- VCF 证明器触发的胜利是**数学强制**的（本项目对局中多数胜局以直接连五收束，
  VCF 作为保险层存在）；
- 剩下的部分由 100/100、69/70 这样可复现的实验战绩背书。

若需要理论完备，只能走向专用求解器（VCF/VCT 全量证明或约束搜索），这与
"小模型上手机"是两个方向的目标。

## 10. 第八步：部署到手机（`gomoku/export_onnx.py`）

```bash
python3 -m gomoku.export_onnx --ckpt checkpoints/best.pt --out mobile/models
# gomoku_policy_value.onnx        1114 KB  (fp32)
# gomoku_policy_value.int8.onnx    302 KB  (int8 动态量化) ← 手机用这个
# parity: max |Δpolicy|≈1e-5, max |Δvalue|≈1e-6   ← 与 PyTorch 数值一致性校验
```

要点：

- 导出用经典 TorchScript 路径（`dynamo=False`），对这个规模的模型最稳；
  量化用 `onnxruntime.quantization.quantize_dynamic`，模型从 1.1MB → **302KB**；
- 手机端只需实现三件事：输入编码（4 平面）、`candidates` 剪枝、轻量 MCTS
  （或直接用策略 top-k + 价值加权的浅层搜索）。`mobile/ANDROID.md` 里有可直接
  粘贴的 Kotlin 实现（ONNX Runtime Android）；
- 逻辑层（强制着法/防叉）是纯规则代码，原样翻译成 Kotlin/Java 即可，
  它们不依赖网络，却是棋力下限的保证。

## 12. FAQ

**Q: 为什么不用 DQN？**
棋类动作空间大（225）、奖励极度稀疏且在终局，DQN 的值函数近似在这种设定下
效率很低。策略+价值双头 + 搜索（AlphaZero 范式）利用"搜索结果当标签"，
样本效率高一个量级，是现代棋类 AI 的标准答案。

**Q: 为什么 28 万参数就够？**
因为网络只需要"方向感"，深度思考交给 MCTS。实验里同一个网络在 sims=64 和
sims=256 下棋力差异明显——搜索强度是免费（相对训练而言）的棋力来源。
模型小还带来训练快、部署容易的双重好处。

**Q: 自我对弈会不会自己学歪？**
会（坑 2 就是）。对策：晋级门控（只允许被证明更强的网络上位）、外部对手定期
考核（vs 老师 AI）、老师数据锚定经验池。

**Q: 训练多久能到"很强"？**
本项目 2 小时 CPU+GPU 各司其职就到"对内置对手全胜"。继续加轮次收益递减；
想要质变要加网络规模和自我对弈量（AlphaZero 是千万局级别）。

## 13. 延伸：平移到象棋 / 围棋要改什么

| 模块 | 五子棋（本项目） | 中国象棋 | 围棋 |
|---|---|---|---|
| 状态编码 | 4 平面布尔 | 棋子类型×位置（多平面 one-hot） | 同左 + 提子数/劫 |
| 动作空间 | 225 点 | ~4096（from-to） | 361 + pass |
| 规则引擎 | 100 行 | 走子合法性/将军/将死 | 提子/劫/禁着 |
| 终局判定 | 连五 | 将死/困毙 | 双方 pass + 数子 |
| 逻辑保底层 | 连五/堵五/防叉/VCF | 将军逃脱强制着法 | 少（依赖搜索） |
| 经验池规模 | 6 万 | 百万级 | 千万级 |
| 网络 | 4 块×48 | 10 块×128 起 | 20 块×256 起 |

不变的是框架：**规则引擎 → 双头网络 → MCTS → 自我对弈 → 门控晋级 → 评估**。
换棋类主要是换"规则引擎"和"动作/状态编码"，训练循环代码几乎原样复用。
